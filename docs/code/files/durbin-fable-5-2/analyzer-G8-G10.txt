**accuracy.**

- The agent's measurements: candidate/floor 1.00–1.05 in max and 2-norm; candidate/baseline 0.001–0.3 for n > 128 (campaigns S214, S290, S577); bit-identical for n ≤ 128 (S524, S577).

**acceptance:** same-precision. The working precision is kept. The FP32 rounding of the iteration is corrected at float-float anchors, the tolerance (2^-27) lies below the rounding of the FP32 output, and level 1's residual rule accepted every instance. No loss of accuracy exists for the rule to catch.

**Acceptance-rule notes.**

1. **Small n.** The rule compares against "the FP32 original's residual". For small n that residual can be smaller than the residual of the correctly rounded exact solution. The agent measured up to ~2.8× in max norm and ~3.4× in 2-norm, in up to 114 of 600 inputs for n ≤ ~48 (S195). Only the `factor` term (4) leaves room for a more accurate answer there; a factor below ~3.4 would reject the correctly rounded exact solution. The term responsible is the baseline's own residual as the reference. This solution avoids the issue with its bit-exact replica.
2. **Ill-conditioned inputs.** The contract admits any SPD unit-diagonal Toeplitz matrix with values in [-1,1], including near-singular ones. There a residual criterion does not bound the forward error, and the baseline's own result can be non-finite (S279), which leaves the factor × baseline-residual allowance undefined. The verification inputs follow the well-conditioned generator, so this blind spot is not exercised. The solution is at least as accurate as the baseline on such inputs (S279). How level 1 treats a non-finite baseline is unknown.

### G10: Algorithmic changes, and whether they keep the kernel general

**Conclusion:** Every algorithmic change solves the kernel's general problem. That problem is a symmetric positive definite, unit-diagonal Toeplitz (Yule–Walker) system T y = −r, as in Levinson–Durbin linear prediction or AR fitting. The algorithm changes are PCG with an AR(m) Gohberg–Semencul preconditioner, FFT products and a Schur-form direct phase. Hard inputs fall back to an FP64 recursion, so correctness does not depend on the input class. Only the speed relies on the published decaying-coefficient inputs. No bugs on allowed inputs were found by reading.

**Kernel.** PolyBench/C 4.2.1 `durbin` (`KERNEL.json`) is Durbin's algorithm for the Yule–Walker equations: given the normalised autocorrelation r (r0=1), it computes y with T y = −r. It is used in linear prediction (LPC speech coding) and in fitting AR(p) models. The general input is any positive definite autocorrelation sequence, including slowly decaying, narrow-band and near-singular ones.

**Task conditions relied on**

1. **basis: another stated condition** (the published input domain).
   - Property exploited: the self-check generator draws partial coefficients with |k_i| < 0.5/(i+1) (read from check-example, S592–S593), so an AR(253) model matches the spectrum and PCG reaches the floor in 4–6 iterations (S595). The fixed prefix is sized for that class. This is speed only; correctness does not depend on it.
   - Why not general: real autocorrelations (narrow-band spectra, AR processes with poles near the unit circle, spectra with zeros) have reflection coefficients that do not decay like 0.5/(i+1). There the solution is still correct but slower, through the WHILE loops or the FP64 fallback at ~1.9 µs per step (S241), i.e. on the order of 0.2 s at n=1e5.
   - What the contract or inputs should say: if the benchmark means to score the general case, include verification inputs with slowly decaying or near-unit reflection coefficients (for example AR(1) with ρ=0.999, or sinusoids plus noise). Otherwise state the decay condition in the contract.
2. **basis: code path our tests never ran.**
   - Property exploited: none. The FP64 fallback, and probably the slow-path WHILE loops, are not reached by the verification instances.
   - Why not general: the level-1 times are fast-path times; a fallback at n=2003 would take milliseconds by S241, yet 167 µs was measured. Whether any instance needed an extra iteration through the slow path is unknown.
   - What the contract or inputs should say: one ill-conditioned SPD instance (for example r_k = 0.999999^(k+1), where the agent's run took the fallback at S279) would exercise and verify the fallback.

**Bugs on allowed inputs:** none found by reading. The allowed domain is any SPD unit-diagonal sequence in [-1,1] of realistic size; extreme dimensions are not considered. Not tested in the record: a forced or natural fallback on the FFT path (n > 5120), since the agent forced the fallback only up to n=3000 (S241) and reached it naturally up to n=5000 (S279). A test would force `IC_FORCEFAIL` at n≈1e5 and compare the residual with the floor.

**Summary.** The solution changes the algorithm (iterative PCG with FFT products and a Gohberg–Semencul preconditioner, plus a Schur-form direct phase). That is allowed because it solves the general SPD Toeplitz system, and it keeps a guaranteed FP64 path for inputs the iteration cannot handle. The narrow published input class makes the solution fast but is not needed for it to be correct. The verification never exercises the fallback.
