### G9: Precision, and whether the acceptance caught its effect

**Conclusion:** `same-precision`, in fact higher. The direct engines repeat the FP32 baseline's operations in its order and are bit-identical to it. The spectral engines compute in double-float (~48-bit significand) and round once to FP32, with an error of about 3e-8, about 20x below the CPU FP32 baseline. Level 1 accepted every instance. The acceptance rule's max-over-array term makes pure FP32 spectral methods fail on constant inputs, which is a property of the rule.

**Precision used.**

- **Agent**:
  - Spectral error against a GPU-FP64 stencil ≤ 2.98e-8 for n1=1,300–13,000, against CPU FP32's 4.9e-7–6.9e-7 (S109, S253).

**Acceptance**: same-precision. No arithmetic below FP32 is used, and the accuracy is better than the baseline's. A loss could not be caught because none occurred. On random inputs at the scored size the allowance is about 5.6e-6, about 200x the solution's error, which fits margin 0.005. The rule would accept far less accurate results there.

**Acceptance-rule note.** The term `factor·max_over_the_array|cpu_baseline − reference|` is zero on inputs where the FP32 baseline is exact, such as constant fields (S27: base error 0.000 for const 1.0 and 0.7). The allowance there falls to atol + 4·eps·|ref| ≈ 1.14e-7 + 4.8e-7·|ref|. An FP32 transform-based evaluation of the same linear map (FFT or GEMM DST) has rounding errors of 1.5e-6 to 1.2e-5 on such inputs (agent's S29, "ones"), so it would be rejected although its deviation is rounding only. The agent named this risk (NOTES.md:27) and paid for it with double-float. A constructed input would be a constant interior and borders (e.g. all 0.7) with n1 ≥ 1,024 and any n0. Not tested.

### G10: Algorithmic changes, and whether they keep the kernel general

**Conclusion:** Every algorithmic change is general for jacobi-2d. The spectral solution is an exact reformulation of the same linear map for any square grid, any interior, any borders and any n0 ≥ 1, and Bluestein and Bailey are exact DFT algorithms. The one gap is a code path level 1 never ran: its correctness instances reach only the direct engines. No open bugs remain on allowed inputs; one launch-limit bug was found and fixed in the session.

The kernel (KERNEL.json: PolyBench/C 4.2.1 jacobi-2d) performs, for t < TSTEPS, `B = 0.2·(A_c + A_w + A_e + A_s + A_n)` then `A = 0.2·(...B...)` on the interior of an N×N grid. The borders are never written. Here N = n1 and TSTEPS = n0; the agent's reading is in NOTES.md:5. The operator is linear with constant coefficients and constant Dirichlet data, which is the setting in which sine transforms diagonalise the 5-point stencil.
