### G10: Algorithmic changes, and whether they keep the kernel general

**Conclusion:** All changes are general. The solution makes four algorithmic changes against PolyBench nussinov (`KERNEL.json`): a tiled evaluation order, exact sparse split candidates, a tile-wide closure with extension weights, and tighter tie pruning. Each computes the general Nussinov recurrence exactly for any integer table and sequence; only the speed depends on how sparse the candidates are. No task condition was exploited, and no defect on allowed inputs was found by reading.

**The kernel.** Nussinov's algorithm is the interval dynamic program for maximum base-pair matching in RNA secondary-structure prediction (Nussinov, Pieczenik, Griggs and Kleitman, "Algorithms for loop matchings", SIAM J. Appl. Math. 35(1):68–82, 1978). PolyBench/C 4.2.1 `medley/nussinov` computes it with a cubic split loop; as far as the analyst recalls, PolyBench initialises the table to 0. This task's baseline (S3) is the same loop nest with an arbitrary initial table in [−256, 256] and bases 0..3. It reads the original subdiagonal for adjacent endpoints, and its split excludes a one-element left piece (k from i+1).

**Changes**

| change | file:line | general | why | sources | tests |
|---|---|---|---|---|---|
| Tiled evaluation order: diagonal tiles first, then rectangles by tile gap, one launch per tile diagonal | solution.cu:18-58, 60-194, 205-216 | yes | an interval needs only shorter intervals, which lie in earlier tile diagonals or are resolved inside the rectangle by the closure; the order is a schedule, not an approximation | standard blocked or wavefront schedules of interval DPs | harness (S324), level 1 |
| Exact sparse split candidates: per column, the starts of right operands that no skip, split or outer prefix can reproduce, kept without cap (capacity for every earlier start) | solution.cu:77, 96-100, 168-192, 254, 260-261 | yes | a split whose right operand is itself derived by a skip or split, or can be absorbed into the outer prefix, is dominated by another legal derivation; keeping all irreducible operands preserves the maximum for any values; dense lists cost only time ("Dense lists can still give cubic work", NOTES.md:20) | the sparsification technique for RNA-folding DPs (Wexler, Zilberstein and Ziv-Ukelson, J. **Task conditions relied on:** none. The algorithm uses no property of the evaluation inputs. The −∞ sentinel `INT_MIN/2` (solution.cu:9) and the int sums assume scores far from the int limits.
